I've always had a natural affinity for the native text-editing
interface in [[https://www.gnu.org/software/emacs/][Emacs]]. The shortcuts (called key-bindings in Emacs
terminology) and mnemonic patterns make intuitive sense to me. So for
nearly 2.5 decades, I happily used Emacs as "just a text editor."

In late 2023, I decided to immerse myself in the world of [[https://www.gnu.org/software/emacs/manual/html_node/elisp/][Emacs Lisp]].
This really wasn't driven by any specific goal; it was simply me
encouraging my curiosity. It was around this time that it hit me:

#+begin_quote
Emacs is not a text editor, it's a tool construction kit that lets you
build any text-based tool you want. /It is the embodiment of a
philosophy of user empowerment./
#+end_quote

As I've explored the implications of this idea, my Emacs configuration
has evolved significantly. It's no longer limited to a handful of
snippets I've cribbed from the internet. It now involves multiple
packages, relies on [[https://melpa.org][a package repository]], leans into powerful systems
built upon Emacs (like [[https://magit.vc][Magit]] and [[https://orgmode.org][Org Mode]]), and most importantly,
adapts Emacs to be exactly what I need it to be.

This file gathers all these ideas in one place, and it aims to be two
things simultaneously:

- Literature that is readable and understandable for humans.
- A resource that can be directly exported (=C-c C-v t= in Org Mode)
  to my actual Emacs configuration files.

The structure of this file was inspired by [[https://protesilaos.com/emacs/dotemacs][a much richer literate
configuration by Prot]].

[[mailto:mail@harishnarayanan.org][Please write to me]] if you need any help with how it's used, or if
you'd like to suggest any improvements.

* Early Initialisation

There are some things (mostly pertinent to the base UI) that need to
be set really early in Emacs' startup. This is so that the UI doesn't
first show up uncustomised, and then /flash/ as it redraws based on any
later UI customisation (such as a change of theme).

This early initialisation configuration goes into a handily-named file
called =early-init.el=.

** File Header

If you learnt to program in the last 25 years, you've probably only
been exposed to one form of variable scoping: /lexical/ scoping. It's
so ingrained that you might never have needed a name for it. It simply
means that variables are scoped to the local context they're
introduced in.

Emacs is a program from a different era, and it has a particularly
deep reason for not wanting variables defined this way. Emacs Lisp
uses /dynamic/ scoping by default, which you can think of as a large,
global scope. This is rather cool: if you change something (a colour,
say) in one place, it immediately and magically applies everywhere
that variable is referenced.

As convenient as that is, it is also very unsafe, and a source of many
a bug as code is hard to isolate. To account for this, modern Emacs
does allow for lexical scoping per file, even though it isn't the
default everywhere. And since ours is new code sitting atop this
creaky foundation, we make sure at least our code is lexically scoped.

#+begin_src emacs-lisp :tangle "early-init.el"
;; -*- lexical-binding: t -*-
#+end_src

** Clean Slate

Depending on your system, there might be some default configuration
shared by other Emacs users in a file called =default.el=. To ensure
our Emacs behaves consistently everywhere, we ignore this and start
from a blank slate.

#+begin_src emacs-lisp :tangle "early-init.el"
(setq inhibit-default-init t)
#+end_src

** Minimal Interface

There are a few elements like a graphical menu and a scroll-bar that
are useful for beginners when first getting acquainted with Emacs. But
as you get more experienced navigating the app with a keyboard, they
get less useful. As a more advanced user, I remove them from the UI to
let me focus more on the content.

#+begin_src emacs-lisp :tangle "early-init.el"
(menu-bar-mode -1)
(tool-bar-mode -1)
(scroll-bar-mode -1)
#+end_src

In the snippet above, =-1= is convention for disabling the
corresponding mode.

** macOS System Integration

I generally use Emacs on macOS, and this needs me to tweak it a tiny
bit to my liking.

*** Resolve native compilation issues

To be as fast as possible, modern Emacs /byte compiles/ Emacs Lisp
code into an efficient format for use at runtime. For some reason, on
my Mac, Emacs fails to fully understand where GCC is installed, and
then complains that it cannot find =libgccjit.so= very many times when
installing packages.

No matter, we help it along by explicitly telling it where to look.

#+begin_src emacs-lisp :tangle "early-init.el"
(when (eq system-type 'darwin)
  (add-to-list 'exec-path "/opt/local/bin")
  (setenv "PATH" (concat "/opt/local/bin:" (getenv "PATH"))))
#+end_src

The paths above are hard-coded for [[https://www.macports.org][MacPorts]] and you can tweak them for
your system if it's different.

*** Set the Command key to function as the Meta key

Emacs has two primary modifier keys, the Control key (=C=) and the
Meta key (=M=). =M= is traditionally mapped to =Alt= on most
keyboards, but on a Mac, =Command= is so much more comfortable.

#+begin_src emacs-lisp :tangle "early-init.el"
(when (eq system-type 'darwin)
  (setq mac-command-modifier 'meta
        mac-option-modifier 'none))
#+end_src

*** Reduce window decoration

These settings make Emacs' titlebar blend more seamlessly with the
dark theme. Enforcing night mode ensures that the title is in a colour
that is visible against the dark titlebar.

#+begin_src emacs-lisp :tangle "early-init.el"
(when (eq system-type 'darwin)
  (add-to-list 'default-frame-alist '(ns-transparent-titlebar . t))
  (add-to-list 'default-frame-alist '(ns-appearance . dark)))
#+end_src

** Performance Optimisation

*** Reduce pauses from garbage collection

As Emacs runs, it allocates memory from the operating system to store
the data it needs. When tasks complete, not all of this data needs to
persist and can be discarded. To find and reclaim this unused memory,
Emacs runs a [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Garbage-Collection.html][garbage collection]] process after:

- a certain number of bytes have been allocated, or
- a certain fraction of the current heap size has been used up

since the previous garbage collection.

The trouble is, the default thresholds for these are quite low, e.g.
800,000 bytes (~800 kB) on a 64-bit computer. This means garbage
collection triggers unnecessarily often, causing noticeable pauses
that slow things down.

To address this, we follow an approach that traces back to [[https://lists.gnu.org/archive/html/emacs-devel/2020-11/msg00761.html][Andrea
Corallo]]. We defer garbage collection entirely during startup and
minibuffer activity to keep the experience snappy, then restore it to
a reasonable threshold (64 MB) for normal editing.

#+begin_src emacs-lisp :tangle "early-init.el"
(setq gc-cons-threshold most-positive-fixnum
      gc-cons-percentage 1.0)

(defconst hn/gc-normal-threshold (* 64 1024 1024)) ;; 64MB
(defconst hn/gc-normal-percentage 0.1)

(add-hook 'emacs-startup-hook
          (lambda ()
            (setq gc-cons-threshold hn/gc-normal-threshold
                  gc-cons-percentage hn/gc-normal-percentage)))

(add-hook 'minibuffer-setup-hook
          (lambda () (setq gc-cons-threshold most-positive-fixnum)))

(add-hook 'minibuffer-exit-hook
          (lambda () (setq gc-cons-threshold hn/gc-normal-threshold
                           gc-cons-percentage hn/gc-normal-percentage)))
#+end_src

*** Reduce file-handler overhead during startup

Every time Emacs touches a file path, it runs through
=file-name-handler-alist= to match the file with its corresponding
/handler/ (e.g. =image-file-handler= for =.png=). Now when opening a
single file, this is exactly what we want, and the cost is negligible.
But at startup, Emacs =load=s hundreds of small Elisp libraries, none
of which trigger any actual handlers. To side-step this overhead, we
clear out the alist before startup and restore it after via
=emacs-startup-hook= once we're up.

#+begin_src emacs-lisp :tangle "early-init.el"
(defvar hn/file-name-handler-alist-backup file-name-handler-alist)
(setq file-name-handler-alist nil)
(add-hook 'emacs-startup-hook
          (lambda ()
            (setq file-name-handler-alist
                  (delete-dups (append file-name-handler-alist
                                       hn/file-name-handler-alist-backup)))))
#+end_src

** Separate =customize= settings

In addition to being configured with the source code in this file,
Emacs can also be configured using a graphical interface (=M-x
customize=). When using this GUI, the standard behaviour is to persist
these settings directly by editing the default Emacs config file.

The following configuration puts this into its own file, so we can
clearly separate these two concepts.

#+begin_src emacs-lisp :tangle "init.el"
(setq custom-file (locate-user-emacs-file "custom.el"))
(load custom-file 'noerror 'nomessage)
#+end_src

* Package Management

In addition to the packages that come built-in with Emacs, there is a
lot out there that can add to its functionality. We turn to a popular,
community-driven package repository called [[https://melpa.org/][Melpa]] to access this
goodness.

** Repository Configuration

To access Melpa, we add its URL alongside the default GNU ELPA archive
Emacs already comes with.

#+begin_src emacs-lisp :tangle "init.el"
(require 'package)
(add-to-list 'package-archives '("melpa" . "https://melpa.org/packages/") t)
#+end_src

** =use-package= Setup

[[https://www.gnu.org/software/emacs/manual/html_node/use-package/][=use-package=]] is a macro that lets us declare each package and its
configuration as a single block, rather than scattering installation,
loading, and configuration logic across the file. The
=use-package-always-ensure= variable I set below /ensures/ that all
packages are installed from the archives if not present locally.

#+begin_src emacs-lisp :tangle "init.el"
(require 'use-package)
(setq use-package-always-ensure t)
#+end_src

In some cases, I want to explicitly use packages that come prebuilt
into Emacs, and in those cases I opt out of this behaviour with
=:ensure nil=. You'll see this later on.

** Optimisation Notes

In the sections that follow, I use =use-package= to install, configure
and load multiple packages. Loading all packages at startup can slow
things down significantly (adding multiple seconds to startup time).

To identify which packages are slowing things down, I temporarily
enable statistics collection by adding =(setq
use-package-compute-statistics t)= at the top of =init.el=. After
restarting Emacs, I run =M-x use-package-report= to see a table of
package load times sorted by duration.

Armed with this data, I selectively defer expensive packages so they
only load when actually needed. The configurations below reflect this
optimisation. I've deferred heavy packages to keep startup fast.

* Appearance and Interface

Emacs is an old program, the current incarnation of which traces its
roots back to the early 1980s. The following settings are small tweaks
that make it look a bit more modern.

** Frame and Window Behaviour

*** Frame title format

I like seeing the current buffer name and the machine I'm on right in
the title bar, so I don’t lose track when I have multiple frames or
hosts open.

#+begin_src emacs-lisp :tangle "init.el"
(setq frame-title-format
      (concat "%b - emacs@" (system-name)))
#+end_src

*** Startup screen preferences

I prefer a relatively clean and empty state as I start, so the
following removes a startup splash screen and brings up an empty plain
text buffer, so I can start typing immediately.

#+begin_src emacs-lisp :tangle "init.el"
(setq inhibit-startup-screen t
      initial-scratch-message ""
      initial-major-mode 'text-mode)
(setq-default major-mode 'text-mode)
#+end_src

If you are new to Emacs Lisp, you might be curious why the first three
variables above are =setq=, whereas the last one is =setq-default=.
Notice that the first three are ordinary global variables. Each holds
a single value Emacs uses everywhere, so they only need =setq=. The
last one, =major-mode=, is /automatically buffer-local/, which means
that every buffer carries its own copy and it needs to be set every
time a new buffer is opened. This is what =setq-default= does.

*** Prevent accidental zooming of text

On my Mac, I sometimes accidentally trigger zooming of text because I
have my hand on the =C= key and scroll on the trackpad. The following
configuration ignores this input.

#+begin_src emacs-lisp :tangle "init.el"
(when (eq system-type 'darwin)
  (define-key key-translation-map (kbd "C-<wheel-up>")   (kbd "<wheel-up>"))
  (define-key key-translation-map (kbd "C-<wheel-down>") (kbd "<wheel-down>"))
  (define-key special-event-map [pinch] #'ignore))
#+end_src

** Theme Configuration

The basic visual styling of my Emacs is controlled by a highly
accessible theme called [[https://protesilaos.com/emacs/modus-themes][Modus Vivendi Tritanopia]]. A version of this
theme comes built-in with Emacs, but it is not the most up-to-date
version. We fetch the most recent version from the package repository
and customise it a little. This is a highly customisable theme with
many options, but I try to keep it simple.

#+begin_src emacs-lisp :tangle "init.el"
(use-package modus-themes
  :demand t
  :custom
  (modus-themes-italic-constructs t)
  (modus-themes-bold-constructs t)
  (modus-themes-prompts '(bold))
  (modus-themes-to-toggle '(modus-operandi-tritanopia modus-vivendi-tritanopia))
  (modus-themes-common-palette-overrides
   '((border-mode-line-active bg-mode-line-active)
     (border-mode-line-inactive bg-mode-line-inactive)))
  (modus-themes-headings
   '((1 . (1.2))
     (2 . (1.1))
     (agenda-date . (1.1))
     (agenda-structure . (1.2))
     (t . (1.0))))
  :config
  (modus-themes-load-theme 'modus-vivendi-tritanopia)
  :bind (("<f5>" . modus-themes-toggle)))
#+end_src

** Visual Feedback Systems

*** Selection Behaviour

In most modern editors, when you select some text, you can see that
region highlighted. And when you start typing, the text you type
replaces your selection. These settings make Emacs behave in that way.

#+begin_src emacs-lisp :tangle "init.el"
(transient-mark-mode 1)
(delete-selection-mode 1)
#+end_src

*** Editor Visual Aids

It is nice to see matching parentheses (immediately) and the cursor's
column number, especially when editing code. So we turn these on.

#+begin_src emacs-lisp :tangle "init.el"
(setq show-paren-delay 0)
(show-paren-mode 1)
(column-number-mode 1)
#+end_src

** Smooth Scrolling

Modern Emacs supports pixel-by-pixel scrolling, which feels much more
natural on a trackpad than the default line-by-line stepping
behaviour.

#+begin_src emacs-lisp :tangle "init.el"
(pixel-scroll-precision-mode 1)
#+end_src

** Whitespace and Buffer Boundaries

Now we go on to add a few small visual cues:

- trailing whitespace is highlighted so we don't accidentally save it,
- empty lines at the end of a buffer are similarly marked,
- buffer boundaries are shown as arrows on the right edge, and
- we use a single space after full-stops as convention.

#+begin_src emacs-lisp :tangle "init.el"
(setq-default show-trailing-whitespace t
              indicate-empty-lines t
              indicate-buffer-boundaries 'right
              sentence-end-double-space nil)
#+end_src

It is convenient to automatically copy mouse-selected text. It makes

(setq mouse-drag-copy-region t)
#+end_src

** Better Keyboard Quit Behaviour

The default keybinding to abort whatever is going on (=C-g=) is really
limited. In all but the most standard cases, it will not work because
more often than not, your focus is not where the thing you want to
abort is. To work around this, [[https://protesilaos.com/emacs/dotemacs][Prot]] maintains a small /Do-What-I-Mean/
wrapper that properly closes and aborts things in a range of cases,
and falls back to a plain =keyboard-quit= otherwise.

I reproduce his work nearly verbatim (I go from the namespace =prot-=
to =prot/= to fit my own style) and bind that to =C-g=.

#+begin_src emacs-lisp :tangle "init.el"
(defun prot/keyboard-quit-dwim ()
  "Do-What-I-Mean variant of `keyboard-quit' that closes the obvious thing in scope."
  (interactive)
  (cond
   ((region-active-p)
    (keyboard-quit))
   ((and (derived-mode-p 'completion-list-mode 'special-mode)
         (not (one-window-p)))
    (quit-window))
   ((when-let* ((_ (not (one-window-p)))
                (windows (seq-filter
                          (lambda (window)
                            (with-selected-window window
                              (derived-mode-p 'completion-list-mode 'special-mode)))
                          (window-list))))
      (dolist (window windows)
        (quit-window nil window))))
   ((> (minibuffer-depth) 0)
    (abort-recursive-edit))
   (t
    (keyboard-quit))))

(define-key global-map (kbd "C-g") #'prot/keyboard-quit-dwim)
#+end_src

* File Handling

** Safer File Deletion

Some pathways to file deletion in Emacs (either directly via
=delete-file= or via =dired='s =D=) permanently delete files without
giving you an option to undo. I have definitely lost data this way
before. I lived with this for a while until I noticed =magit='s =k=
routes file deletions through the system trash for safety.

This then prompted me to look up the mechanism, and of course you can
configure Emacs to route all deletions this way, allowing you to
restore things later if needed.

#+begin_src emacs-lisp :tangle "init.el"
(setq delete-by-moving-to-trash t)
#+end_src

* Editing Foundations

** Indentation and Whitespace

I use spaces rather than tabs, and prefer a two-space width.

#+begin_src emacs-lisp :tangle "init.el"
(setq-default indent-tabs-mode nil
              tab-width 2)
#+end_src

** Up- and Down-Casing

For some reason, Emacs ships with two very useful commands
(=upcase-region= and =downcase-region=) disabled. So I turn them back
on.

#+begin_src emacs-lisp :tangle "init.el"
(put 'downcase-region 'disabled nil)
(put 'upcase-region 'disabled nil)
#+end_src

** Unfilling Paragraphs

Emacs has the native functionality to "fill a paragraph" (=M-q=),
which is to take long lines or otherwise unruly text and neatly lay
them out as paragraphs. But it has no in-built mechanism to do the
inverse, so this third-party package fixes that. You can now
=unfill-paragraph= back to a long, single line.

#+begin_src emacs-lisp :tangle "init.el"
(use-package unfill)
#+end_src

** Spelling

Emacs comes with a built-in spell-checker called [[https://www.gnu.org/software/emacs/manual/html_node/emacs/Spelling.html][Flyspell mode]] that
automatically checks your spelling as you type. I have used this for
many years, but in large documents it can be very slow and hampers
smooth scrolling.

The community has largely moved onto a third-party package called
[[https://github.com/minad/jinx][=jinx.el=]], which is a really fast just-in-time spell-checker, and
that's what I am switching to too.

For this to work, you need a few system packages installed. For me
(using MacPorts), these are:

- =aspell=
- =aspell-dict-en=
- =enchant2 +aspell=

#+begin_src emacs-lisp :tangle "init.el"
(use-package jinx
  :hook ((text-mode . jinx-mode)
         (prog-mode . jinx-mode))
  :bind ([remap ispell-word] . jinx-correct)
  :custom
  (jinx-languages "en_GB"))
#+end_src

* Minibuffer and Completion

** Minibuffer

The minibuffer is the small interface at the bottom of the Emacs
window where you can enter commands, input parameters, see results of
these commands and so on.

Whenever you type in the minibuffer (a command, a file path, a buffer
to switch to), Emacs offers helpful (auto)completion. The default
experience is functional but plain: you press =TAB= and a separate
buffer pops up with candidates. Over time, different packages have
come and gone to make this experience feel a bit more fluid, but what
you see below is a fairly modern set.

[[https://github.com/minad/vertico][=vertico=]] shows the candidate list inline, as a vertical menu below
the minibuffer.

#+begin_src emacs-lisp :tangle "init.el"
(use-package vertico
  :custom
  (vertico-resize t)
  :init
  (vertico-mode))
#+end_src

[[https://github.com/radian-software/prescient.el][=vertico-prescient=]] reorders that list so the things I pick most often
surface first.

#+begin_src emacs-lisp :tangle "init.el"
(use-package vertico-prescient
  :after vertico
  :config
  (vertico-prescient-mode 1)
  (prescient-persist-mode 1))
#+end_src

[[https://github.com/minad/marginalia][=marginalia=]] adds useful context next to each candidate: a brief
docstring next to a command, a file's size and mode next to a path,
and so on.

#+begin_src emacs-lisp :tangle "init.el"
(use-package marginalia
  :init
  (marginalia-mode))
#+end_src

[[https://github.com/oantolin/orderless][=orderless=]] makes text matching far more forgiving. Each
space-separated fragment of my query can appear anywhere in a
candidate, in any order.

#+begin_src emacs-lisp :tangle "init.el"
(use-package orderless
  :custom
  (completion-styles '(orderless basic))
  (completion-category-defaults nil)
  (completion-category-overrides '((file (styles partial-completion)))))
#+end_src

Persistence across sessions comes from two packages built into Emacs.
=savehist= keeps minibuffer history (so my last few =M-x= choices are
still there next time I launch Emacs), and =recentf= tracks recently
opened files.

#+begin_src emacs-lisp :tangle "init.el"
(use-package savehist
  :ensure nil
  :init
  (savehist-mode))

(use-package recentf
  :ensure nil
  :init
  (recentf-mode)
  :custom
  (recentf-max-saved-items 100))
#+end_src

[[https://github.com/minad/consult][=consult=]] adds smarter commands for common minibuffer-driven actions.
It can do a whole lot more (that I should probably consider in the
future). For now, the one I bind here is =consult-buffer=, which
unifies switching to any buffer or recently-visited file.

#+begin_src emacs-lisp :tangle "init.el"
(use-package consult
  :bind (("C-x b" . consult-buffer)))
#+end_src

** In-buffer completion

In the preceding section, we focused a lot on completion in the
minibuffer. But the same applies even when typing in any buffer, such
as having function names auto-complete when writing code. Here too, we
can rely on modern packages and customisations to refine the native
UI.

[[https://github.com/minad/corfu][=corfu=]] replaces the native UI (which pops up in a separate buffer)
with a small popup right at the cursor, narrowing as I type and
accepting with =RET=.

#+begin_src emacs-lisp :tangle "init.el"
(use-package corfu
  :custom
  (corfu-cycle t)
  (corfu-preselect 'prompt)
  (corfu-scroll-margin 5)
  (corfu-separator ?\s)
  :init
  (global-corfu-mode)
  :config
  (corfu-popupinfo-mode))
#+end_src

A handful of built-in Emacs settings round the experience off:

- =TAB= indents when there is room to indent and offers completion
  otherwise,
- recursive minibuffer interactions are allowed (so a completion can
  happen inside another), and
- =M-x= hides commands that don't apply to the current major mode.

#+begin_src emacs-lisp :tangle "init.el"
(use-package emacs
  :ensure nil
  :custom
  (tab-always-indent 'complete)
  (completion-cycle-threshold 3)
  (enable-recursive-minibuffers t)
  (read-extended-command-predicate #'command-completion-default-include-p)
  (minibuffer-prompt-properties
   '(read-only t cursor-intangible t face minibuffer-prompt)))
#+end_src

* Programming Infrastructure

General programming-time scaffolding: indentation defaults, syntax
highlighting via tree-sitter, and (eventually) Eglot configuration
that applies across languages.

** Basic Indentation

When I am in a C-family or HTML buffer, I prefer BSD-style braces and
a two-space offset for both.

#+begin_src emacs-lisp :tangle "init.el"
(setq c-default-style "bsd")
(setq-default c-basic-offset 2)
(setq-default sgml-basic-offset 2)
#+end_src

** Syntax Highlighting

In order to colour program source correctly, we need to first go from
the plain text of the program to a /syntax tree/. A modern library for
doing this is called [[https://tree-sitter.github.io/tree-sitter/][Tree-sitter]], which is [[https://www.gnu.org/software/emacs/manual/html_node/elisp/Parsing-Program-Source.html][natively wrapped]] in Emacs.
This wrapper in turn relies on language-specific grammars that I
already have on my Mac via MacPorts. So I point Emacs in the right
direction rather than have it compile its own copies.

#+begin_src emacs-lisp :tangle "init.el"
(when (eq system-type 'darwin)
  (add-to-list 'treesit-extra-load-path "/opt/local/lib/"))
#+end_src

To actually use these modes when I open files, I rely on
[[https://github.com/renzmann/treesit-auto][=treesit-auto=]], which transparently remaps legacy major modes (like
=python-mode= and =go-mode=) to their =*-ts-mode= equivalents whenever
a grammar is available.

* Language-Specific Configuration

One of my primary uses of Emacs is programming, and here I configure
it for the specific languages I work in. The configuration is fairly
light as built-in major modes and [[https://www.gnu.org/software/emacs/manual/html_node/eglot/][Eglot]] already do a lot of the heavy
lifting.

** Python

Python is the language I write the most. Whenever a Python buffer
opens, I load Eglot, which through a language server (I use [[https://github.com/python-lsp/python-lsp-server][=pylsp=]])
offers me completion, jump-to-definition and find-references, rename
and organise-imports refactors, and on-the-fly diagnostics.

#+begin_src emacs-lisp :tangle "init.el"
(use-package python
  :ensure nil
  :hook (python-base-mode . eglot-ensure))
#+end_src

** Scheme

Scheme is perhaps the most beautiful computer language. I dabble in it
quite a bit, mostly to follow along with [[https://mitpress.mit.edu/9780262510875/structure-and-interpretation-of-computer-programs/][SICP]] and [[https://mitpress.mit.edu/9780262028967/structure-and-interpretation-of-classical-mechanics/][SICM]]. [[https://www.nongnu.org/geiser/][Geiser]] is the
Scheme development environment for Emacs and works with several Scheme
implementations. I configure it to know about both MIT Scheme (with
the =mechanics.com= band loaded for SICM) and Guile.

#+begin_src emacs-lisp :tangle "init.el"
(use-package geiser
  :defer t
  :custom
  (geiser-active-implementations '(mit guile))
  :config
  (setenv "DISPLAY" ":0")
  (add-hook 'geiser-repl-mode-hook 'hn/disable-trailing-whitespace-and-empty-lines))

(use-package geiser-guile
  :defer t
  :custom
  (geiser-guile-binary "/opt/local/bin/guile"))

(use-package geiser-mit
  :defer t
  :custom
  (geiser-mit-binary "/Users/harish/Applications/mit-scheme/bin/mit-scheme")
  :config
  (setenv "MITSCHEME_HEAP_SIZE" "100000")
  (setenv "MITSCHEME_LIBRARY_PATH" "/Users/harish/Applications/mit-scheme/lib/mit-scheme-svm1-64le-12.1")
  (setenv "MITSCHEME_BAND" "mechanics.com"))
#+end_src

** LaTeX

This is here almost only for nostalgic reasons, as once (decades ago!)
I wrote my Ph.D. thesis in LaTeX on Emacs on a Mac. It reminds me of a
simpler time.

The following sets up [[https://www.gnu.org/software/auctex/][AUCTeX]], which is the standard LaTeX editing
environment in Emacs. I force auto-fill on while editing TeX so that
the plain-text diffs stay readable.

#+begin_src emacs-lisp :tangle "init.el"
(use-package tex
  :ensure auctex
  :defer t
  :hook (tex-mode . auto-fill-mode))
#+end_src

** File Associations

By default, Emacs opens =.m= files in Objective-C mode. I work with
[[https://www.gnu.org/software/octave/][Octave]] and MATLAB more often than I do Objective-C, so I claim that
extension for =octave-mode= instead.

#+begin_src emacs-lisp :tangle "init.el"
(add-to-list 'auto-mode-alist '("\\.m\\'" . octave-mode))
#+end_src

* Version Control

Emacs has taken on different roles for me over time. At the moment, it
feels like studying diffs and merging changes neatly is my primary
usage of Emacs. For this, I rely a lot on Emacs' built-in diff viewer
and the amazing Magit.

** Magit

If there is one reason to use Emacs, it is [[https://magit.vc][Magit]]. Magit is a friendly
and efficient user interface that wraps git commands. You can do
fairly sophisticated revision control operations simply by selecting
pieces of text and hitting a few keys.

It's basically magic.

#+begin_src emacs-lisp :tangle "init.el"
(use-package magit
  :defer t)
#+end_src

** Diff and Merge

Out of the box, =ediff= splits its panes vertically and pops up a
separate control frame, both of which I find awkward. I switch the
split to horizontal so I can see the two file versions side by side,
and I keep the control buffer at the bottom of the same frame.

#+begin_src emacs-lisp :tangle "init.el"
(setq ediff-split-window-function 'split-window-horizontally)
(setq ediff-window-setup-function 'ediff-setup-windows-plain)
#+end_src

* Custom Functions

These are specific to my needs, and are likely not useful for other
people. They are prefixed with my initials, =hn/=.

** Journal Management

#+begin_src emacs-lisp :tangle "init.el"
(defun hn/journal-todo (start-date end-date &optional prefix)
  "Generate a todo list for journal entries from START-DATE to END-DATE with an optional PREFIX."
  (interactive
   (list
    (read-string "Enter start date (YYYY-MM-DD): ")
    (read-string "Enter end date (YYYY-MM-DD): ")
    (read-string "Enter prefix: " "Write a journal entry for ")))
  (let* ((start-time (date-to-time start-date))
         (end-time (date-to-time end-date))
         (one-day (seconds-to-time 86400)) ; 24 hours * 60 minutes * 60 seconds
         (current-time start-time))
    (while (time-less-p current-time (time-add end-time one-day))
      (let ((entry-date (format-time-string "%A %d-%m-%Y" current-time)))
        (insert (format "%s%s\n" (or prefix "** Write entry for ") entry-date)))
      (setq current-time (time-add current-time one-day)))))
#+end_src

** Buffer Display Customisation

#+begin_src emacs-lisp :tangle "init.el"
(defun hn/disable-trailing-whitespace-and-empty-lines ()
  "Disable showing trailing whitespace and indicating empty lines in the current buffer."
  (setq-local show-trailing-whitespace nil)
  (setq-local indicate-empty-lines nil))
#+end_src

** Section Dividers in Python Files

#+begin_src emacs-lisp :tangle "init.el"
(defun hn/python-insert-section-divider (title)
  "Insert a simple Python section divider around TITLE."
  (interactive "sSection title: ")
  (let* ((width 69)
         (bar (make-string width ?-)))
    (insert (format "# %s\n# %s\n# %s\n" bar title bar))))

(with-eval-after-load 'python
  (define-key python-base-mode-map (kbd "C-c d") #'hn/python-insert-section-divider))
#+end_src
